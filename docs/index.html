1 · Зачем нужен Claude-проект

Чат забывает.
Проект помнит.

Когда делаешь рилзы каждую неделю, быстро надоедает одно и то же: заново рассказывать, в каком ты стиле работаешь, какие у тебя герои, как должен выглядеть промпт и чего делать нельзя. Каждый новый чат начинается с нуля.

Claude-проект решает это. Это отдельная папка внутри Claude, где лежит всё, что должно быть у Claude под рукой в каждом чате.

Инструкции: короткие правила, как Claude должен с тобой работать. Файлы: то, что ты загружаешь сам: описания героев, правила промптов, журнал рилзов, чек-листы. Память проекта: то, что Claude запоминает из ваших чатов сам. Скиллы: готовые рецепты для повторяющихся задач (подробнее о них в разделе 5).

Ты открываешь новый чат внутри проекта, пишешь «новый рилз», и Claude уже в курсе: кто твои герои, какой у тебя стиль, какие ошибки уже были. Проект нужно настроить один раз, и в этом гайде мы пройдём все шаги.

Что это даёт на практике (на моём примере)

  • Герои не путаются. Claude помнит всех героев и их внешность.
  • Нет повторных ошибок. Каждый промпт проходит одну и ту же проверку, прошлые ошибки не повторяются.
  • Всё по моим правилам. Идеи, подпись и теги делаются так, как я привык, объяснять не надо.
  • Можно вернуться через неделю. Всё на месте, ничего не потерялось.

Это не про «умнее». Это про «не объяснять заново».

1 · Why use a Claude Project

Chats forget.
Projects remember.

If you make Reels every week, one thing gets old fast: explaining yourself again and again. Your style, your characters, what a good prompt looks like, what to avoid. Every new chat starts from zero.

A Claude Project fixes that. It's a separate folder inside Claude that holds everything Claude should have at hand in every chat.

Instructions: short rules for how Claude should work with you. Files: what you upload yourself: character descriptions, prompt rules, a log of your Reels, checklists. Project memory: what Claude remembers from your chats on its own. Skills: ready-made recipes for tasks you repeat (more about them in section 5).

You open a new chat inside the project, type "new Reel", and Claude is already up to speed: who your characters are, what your style is, which mistakes have already happened. You set the project up once, and in this guide we go through every step.

What it gives you in practice (my own example)

  • Characters stay consistent. Claude remembers every character and how they look.
  • No repeated mistakes. Every prompt goes through the same check, and past mistakes don't come back.
  • Everything my way. Ideas, captions and hashtags are made the way I like them, no need to explain.
  • Come back a week later. Everything is still there, nothing is lost.

It's not about "smarter". It's about "never explaining again".

3 · Как создать проект

Три шага на компьютере.
Делается один раз.

Настройку удобнее делать на компьютере: там проще загружать файлы и вставлять длинный текст. Когда проект создан, им можно пользоваться и с телефона: выбираешь проект в списке и пишешь в нём, как обычно.

3 · Creating the project

Three steps on your computer.
You only do it once.

It's easiest to set things up on a computer: uploading files and pasting long text is simpler there. Once the project exists you can use it from your phone too: pick the project in the list and write in it as usual.

  1. 1

    Open Claude

    Download and install the Claude desktop app (Windows or Mac): claude.com/download. Open it and sign in. The claude.ai website is the browser version, which lacks some features, so we work in the app.

  2. 2

    Find the projects section

    In the left menu, click Projects.

  3. 3

    Create a project

    Click New project in the top right corner. In the Create a project window, type a name in the first field (What are you working on?): short and clear to you, for example "Reels". In the second (What are you trying to achieve?) write one or two lines about what you do and what you want to achieve. Click Create project.

  4. ✓

    Project created

    You're on the project page: the Instructions and Context blocks on the right, the input box at the bottom. It's empty for now, and that's fine. Next we'll fill it in in the next section.

TipDon't try to do everything at once. Start with a name and add the rest as you go.

4 · Инструкции проекта

Одна фраза, после которой Claude не путается в новом чате.

Каждый новый чат начинается с чистого листа: Claude не помнит вчерашней работы. Поэтому в инструкциях мы велим ему прочитать твой файл с правилами и доложить, что он понял. Правила живут в файле preferences.md, и это обычный текстовый файл.

  1. 1

    Создай файл preferences.md

    Не нужно создавать его вручную: попроси Claude. Открой новый чат внутри проекта и вставь этот запрос со стартовыми правилами:

    Создай файл preferences.md и сохрани его в моём проекте. Запиши в него такие правила работы: 1. Отвечай на том языке, на котором я пишу. 2. Если не хватает данных, сначала задай мне вопросы, а не угадывай. 3. Не придумывай факты. Если не знаешь, так и скажи. 4. Пиши коротко и по делу. 5. Работай по одному шагу и жди моего подтверждения, прежде чем идти дальше.

    Свои правила вписывай вместо этих или вместе с ними. Файл появится в блоке Context.

    Если Claude просто вывел текст в чат и не сохранил файл, напиши ему: «Сохрани этот файл в проекте». Не получилось? Скачай файл и добавь сам: Context → Add.

  2. 2

    Вставь фразу в инструкции

    В блоке Instructions нажми Edit, вставь фразу и нажми Save instructions. Файл с правилами у тебя уже создан, поэтому Claude будет что читать. Кавычки не нужны: кнопка копирует только текст.

    «Прочти preferences.md проекта, затем доложи статус и жди команды.»
    • Прочти файл. Claude узнаёт твои правила, а не угадывает их.
    • Доложи статус. Ты сразу видишь, что он понял. Если что-то упустил, заметишь это в первом ответе, а не после испорченной работы.
    • Жди команды. Он не начинает действовать сам.
  3. 3

    Проверь, что работает

    Убедись, что в блоке Context появился preferences.md. Потом открой новый чат проекта и напиши «Привет». Claude должен ответить примерно так:

    «Прочитал preferences.md. Мои правила: отвечать на твоём языке, задавать вопросы вместо догадок, не придумывать факты, писать коротко, идти по шагам. Жду команды.»

    Слова могут отличаться. Главное, чтобы он перечислил твои правила. Если нет, проверь, что фраза сохранена в Instructions, а файл лежит в Context.

  4. 4

    Дополняй по мере ошибок

    • Записывай правила по мере ошибок. Claude сделал что-то не так? Скажи: «Добавь в preferences.md правило: … и сохрани обновлённый файл в проекте». Файл растёт, ошибки не повторяются.
    • После первого раза не трогай инструкции проекта. Они остаются короткими, всё меняется в файле.
    Показать пример файла, который вырос из практики
    ## ПРИОРИТЕТ: как ко мне обращаться Каждый ответ начинай с моего имени: «Алекс, …». ## ГЛАВНОЕ ПРАВИЛО №1: сначала смотри, потом пиши Перед любым промптом открой и реально посмотри готовую картинку. Не пиши по памяти. Если файл не найден, спроси, где он. ## Протокол начала каждого чата 1. Прочитать этот файл и файл активного проекта. 2. Прочитать нужные SKILL-файлы. 3. Коротко доложить статус и ждать команды. ## Порядок работы над промптом 1. Показать только блок «Проверка», без промпта. 2. Ждать моего подтверждения. 3. После подтверждения показать промпт. По одному за раз. ## Технические правила - При монтаже звук не удалять. - Цветокоррекцию делаем в GPT, не в Grok.
  5. 5

    Когда появятся скиллы, замени фразу

    Скиллы — это файлы-памятки для Claude, подробно о них в разделе 5. Когда они появятся в проекте, фразу в инструкциях нужно заменить на полную, со словами «SKILL-файлы». Мы сделаем это в разделе 5, шаг 1.

    Без «SKILL-файлов» в короткой фразе Claude может не использовать скиллы, и тогда он будет ошибаться там, где скилл уже знает ответ.

СоветНе пиши в preferences.md сразу сто правил. Начни с 3–5 самых важных, остальное добавляй по мере работы.

4 · Project instructions

One sentence so Claude doesn't get lost in a new chat.

Every new chat starts from a blank slate: Claude doesn't remember yesterday's work. So in the instructions we tell it to read your rules file and report what it understood. The rules live in a file called preferences.md, and it's just a plain text file.

  1. 1

    Create the preferences.md file

    No need to create it by hand: ask Claude. Open a new chat inside the project and paste this request with starter rules:

    Create a file preferences.md and save it in my project. Write these working rules into it: 1. Reply in the language I write in. 2. If data is missing, ask me questions first instead of guessing. 3. Don't invent facts. If you don't know, say so. 4. Write briefly and to the point. 5. Work one step at a time and wait for my confirmation before moving on.

    Put your own rules in place of these or alongside them. The file will appear in the Context block.

    If Claude just printed the text in the chat and didn't save the file, tell it: "Save this file in the project." Didn't work? Download the file and add it yourself: Context → Add.

  2. 2

    Paste the sentence into the instructions

    In the Instructions block click Edit, paste the sentence and click Save instructions. The rules file already exists, so Claude has something to read. No quotation marks needed: the button copies only the text.

    “Read the project's preferences.md, then report the status and wait for commands.”
    • Read the file. Claude learns your rules instead of guessing them.
    • Report the status. You see right away what it understood. If it missed something, you notice in the first reply, not after the work is ruined.
    • Wait for commands. It doesn't start acting on its own.
  3. 3

    Check that it works

    Make sure preferences.md appeared in the Context block. Then open a new project chat and write "Hi". Claude should answer roughly like this:

    “I've read preferences.md. My rules: reply in your language, ask questions instead of guessing, don't invent facts, be brief, go step by step. Waiting for commands.”

    Wording may differ. What matters is that it lists your rules. If not, check that the sentence is saved in Instructions and the file is in Context.

  4. 4

    Add to it as mistakes happen

    • Write down rules as mistakes happen. Did Claude do something wrong? Say: "Add a rule to preferences.md: … and save the updated file in the project". The file grows, the mistakes don't repeat.
    • After the first time, don't touch the project instructions. They stay short, everything changes in the file.
    Show an example file that grew from practice
    ## PRIORITY: how to address me Start every reply with my name: "Alex, …". ## MAIN RULE #1: look first, then write Before any prompt, open and actually look at the finished image. Don't write from memory. If the file isn't found, ask where it is. ## Protocol at the start of every chat 1. Read this file and the active project's file. 2. Read the needed SKILL files. 3. Briefly report the status and wait for commands. ## Prompt workflow 1. Show only the "Check" block, without the prompt. 2. Wait for my confirmation. 3. After confirmation, show the prompt. One at a time. ## Technical rules - Don't remove the sound when editing. - We do color correction in GPT, not in Grok.
  5. 5

    When you have skills, swap the sentence

    Skills are memo files for Claude, covered in detail in section 5. Once they're in the project, the sentence in the instructions must be replaced with the full one, with the words "SKILL files". We do it in section 5, step 1.

    Without "SKILL files" in the short sentence, Claude may not use skills, and it will make mistakes where a skill already knows the answer.

TipDon't put a hundred rules into preferences.md at once. Start with 3–5 of the most important and add the rest as you go.

5 · Скиллы для промптов

Скилл — это памятка для Claude по одному сервису.

Правила и причуды сервиса записаны в файле, чтобы не объяснять их в каждом новом чате.

1ПопросиClaude находит правила и создаёт скилл
2ПроверьФайл в проекте, Claude применяет правила
3ДополняйОшибки и находки дописываются в скилл

Скилл становится точнее с каждым рилзом

  1. 1

    Замени фразу в инструкциях

    В блоке Instructions нажми Edit, замени короткую фразу на полную и нажми Save instructions. Теперь Claude будет читать и скиллы:

    «Прочти preferences.md проекта и все релевантные SKILL-файлы, затем доложи статус и жди команды.»

    Это моя фраза. Без «SKILL-файлов» Claude может не использовать скиллы и ошибаться там, где скилл уже знает ответ. Скилл — это файл-памятка, его мы создадим следующим шагом.

  2. 2

    Попроси Claude создать скилл

    Открой новый чат внутри своего проекта и вставь запрос. Подставь свой сервис (Midjourney, GPT, Grok, Nano Banana и другие) и название файла:

    «Найди в интернете правила написания промптов для Midjourney из проверенных источников, в первую очередь официальные. Составь на их основе скилл midjourney-SKILL.md и сохрани файл в проекте. В конце перечисли источники.»

    Если Claude не может искать в интернете, он скажет об этом. Тогда попроси составить скилл по его знаниям и сверь правила с документацией сервиса. Если вместо файла он выдал текст в чат, напиши: «Сохрани этот файл в проекте». Не получилось? Скачай файл и добавь сам: Context → Add.

  3. 3

    Проверь, что получилось

    • Файл на месте. В блоке Context появился midjourney-SKILL.md.
    • Скилл работает. Открой новый чат проекта и попроси: «Сделай промпт для Midjourney». Claude должен действовать по правилам из файла (например, называть их или держаться их порядка). Если нет, проверь, что в инструкциях стоит полная фраза из шага 1.
    • Источники. Просмотри те, что назвал Claude: официальные страницы сервиса надёжнее случайных блогов.
  4. 4

    Дополняй по мере работы

    Промпт не сработал? Скажи:

    «Добавь в midjourney-SKILL.md правило: … Сохрани файл в проекте.»

Скилл нужно обновлять

Скиллы растут вместе с тобой. Меняй скилл, когда:

  • Claude снова и снова делает не то, что тебе нужно (например, пишет слишком длинные сцены). Одна ошибка не повод: её можно просто поправить в чате.
  • У тебя изменилась задача. Например, рилз теперь нужен длиннее 15 секунд и с другой драматической дугой (порядком эмоций от начала до финала).

«Обнови скилл [название скилла, как в Context]: [что изменилось, своими словами]. Сначала покажи, что именно ты изменишь, и ничего не сохраняй. Когда я напишу ок, сохрани копию старого файла как [название]-старый.md, а новую версию сохрани под прежним названием.»

Проверь. Сделай следующий рилз и спроси Claude, какие правила из скилла он применил. Если он назвал новое правило, всё сработало.

Как не потерять работу, когда чат стал слишком длинным

Рилз с десятком правок и версий промпта превращается в очень длинный чат. Чем он длиннее, тем выше риск, что Claude перепутает, какая версия последняя, и забудет договорённости. А новый чат ничего не знает о старом. Выход: перед тем как оставить чат, попроси Claude собрать файл истории, короткую памятку о рилзе. Положи её в проект, и новый чат сможет продолжить с того же места. Проверь это в шаге 4.

Пример из моего проекта

Такой файл у меня есть на каждый рилз. В одном из чатов накопилось 11 версий одного промпта, и Claude начал путать сцены и выдумывать детали, которых нет. Похоже, из-за обилия версий. Я перешёл в новый чат с файлом истории, где было записано, что одобрено, а что нет, и у меня ошибки прекратились. Это один случай, а не гарантия: проверяй каждый раз.

Когда нужен такой файл

  • Рилз закрыт, и ты хочешь убрать чат, не потеряв выводы. Не удаляй старый чат, пока не сделаешь шаг 4.
  • Чат стал тяжёлым: Claude путает версии, повторяет уже отвергнутое, забыл правило. Если рилз ещё не закрыт, продолжай его в новом чате с файлом.
  • Хочешь вернуться к линии через неделю или месяц, например сделать новый рилз с теми же героями.

Что лежит в хорошем файле истории

  • 1Что за рилз и на каком он этапе
  • 2Что одобрено и больше не меняем
  • 3Последние одобренные версии промптов (без черновиков)
  • 4Правила, которые вы придумали вместе
  • 5Ошибки в работе и как их исправили
  • 6Что ещё не решено
  • 7Как продолжить работу в новом чате

Как сделать файл за четыре шага

  1. 1

    Попроси Claude собрать файл

    В том чате, который хочешь закрыть, отправь фразу. Слово в квадратных скобках замени своим названием, латиницей и без пробелов, например dozhd (сами скобки удали). Окончание .md означает обычный текстовый файл, оно остаётся.

    «Составь файл истории этого чата, чтобы я мог продолжить работу в новом чате. Включи: что за рилз и на каком он этапе; что уже одобрено и больше не меняем; последние одобренные версии промптов (без черновиков); правила, которые мы придумали вместе; ошибки в работе и как мы их исправили; что ещё не решено; как продолжить работу в новом чате. Не включай пароли, ключи и личные данные. Назови файл [название]-chat-history.md. Сначала покажи текст в чате. Пока я не напишу ок, файл не создавай и не сохраняй.»
  2. 2

    Прочитай и поправь

    Проверь три вещи: те ли это промпты, которые дали хороший результат (сверь с последним удачным), нет ли лишнего, не пропало ли важное. Что-то не так? Напиши, что именно изменить, например «добавь в раздел с правилами: …» или «убери про…». Claude покажет текст снова: прочти его целиком, а не только изменённое место.

  3. 3

    Сохрани в проекте

    Когда текст верный, напиши «ок, сохрани файл в проекте». Потом открой список файлов проекта и убедись, что файл там. Если его нет, а Claude выдал только текст или файл в чате, скачай файл (или скопируй текст в новый файл .md) и добавь через Context → Add.

    Важно: перед сохранением ещё раз просмотри текст: пароли, ключи и личные данные в файле не нужны.

  4. 4

    Проверь в новом чате

    Это самый важный шаг. Открой новый чат внутри проекта и отправь:

    «Прочти файл [название]-chat-history.md из этого проекта. Если не найдёшь, так и скажи и ничего не придумывай. Затем назови: на каком этапе рилз, какие промпты последние одобренные, какие правила и нерешённые вопросы записаны в файле. Потом жди моей команды.»

    Сверь ответ с файлом. Всё совпало? Продолжай работу. Чего-то не хватает? Вернись в старый чат, попроси дополнить файл, сохрани новую версию под тем же названием и проверь ещё раз. Старый чат можно удалить только после того, как проверка прошла. Если жалко, просто не пользуйся им, но оставь.

Раз в месяц: проверка файлов

Это отдельное дело, нужное, когда в проекте накопится несколько файлов. Они копятся: появляются повторы, то, что уже не так, и правила, которые спорят друг с другом. Claude учитывает все файлы проекта, и если они спорят, он может выбрать не то. Я не удаляю файлы без причины, но раз в месяц прошу Claude их проверить. Сначала скачай важные файлы к себе на устройство, чтобы можно было вернуть прежнюю версию. Потом отправь в чате проекта:

«Проверь все файлы проекта. Найди повторы внутри файлов и между ними, данные, которые, возможно, уже не так, и правила, которые спорят друг с другом. Составь нумерованный список: что предлагаешь удалить, слить или поправить и почему; для каждого пункта назови файл и приведи цитату. Если не уверен, что данные устарели, пометь «не уверен» и не предлагай удалять. Файлы истории разных рилзов не сливай. Ничего не меняй и не удаляй: я посмотрю список и скажу, что делать.»

Что дальше. Просмотри список. Что согласен исправить, напиши: «Сделай пункты 1, 3 и 5 из твоего последнего списка. Покажи новый текст каждого файла и не сохраняй, пока я не напишу ок». Прочти новые тексты целиком: Claude мог незаметно изменить и другие места. Ненужный файл убери из списка файлов проекта сам и только после того, как скачал его копию.

Проверь. В проекте лежит файл истории, а ответ нового чата совпадает с тем, что написано в файле (этап, промпты, правила, нерешённое). Если делаешь проверку файлов раз в месяц: у тебя есть скачанные копии, и ты прочёл новые тексты целиком.

7 · History files

How not to lose your work when a chat gets too long

A reel with a dozen edits and prompt versions turns into a very long chat. The longer it gets, the higher the risk that Claude mixes up which version is the latest and forgets what you agreed on. And a new chat knows nothing about the old one. The way out: before you leave a chat, ask Claude to put together a history file, a short note about the reel. Keep it in your project, and a new chat can pick up where you left off. Test that in step 4.

An example from my project

I have such a file for every reel. In one chat, 11 versions of a single prompt piled up, and Claude started mixing up scenes and inventing details that weren't there. Probably because of all those versions. I moved to a new chat with a history file saying what was approved and what wasn't, and the errors stopped for me. That is one case, not a guarantee: test it every time.

When you need this file

  • The reel is finished, and you want to set the chat aside without losing what you learned. Don't delete the old chat until you've done step 4.
  • The chat has become heavy: Claude mixes up versions, repeats what you already rejected, forgot a rule. If the reel isn't finished, continue it in a new chat with the file.
  • You want to come back to a series in a week or a month, for example to make a new reel with the same characters.

What a good history file contains

  • 1What the reel is and what stage it's at
  • 2What is approved and no longer changes
  • 3Latest approved versions of the prompts (no drafts)
  • 4Rules you came up with together
  • 5Mistakes in the work and how you fixed them
  • 6What is still undecided
  • 7How to continue the work in a new chat

How to make the file in four steps

  1. 1

    Ask Claude to put the file together

    In the chat you want to close, send the phrase. Replace the word in square brackets with your own name, in Latin letters with no spaces, for example rain (and delete the brackets). The ending .md means a plain text file, so keep it.

    “Write a history file of this chat so I can continue the work in a new chat. Include: what the reel is and what stage it's at; what is already approved and no longer changes; the latest approved versions of the prompts (no drafts); the rules we came up with together; mistakes in the work and how we fixed them; what is still undecided; how to continue the work in a new chat. Don't include passwords, keys or personal data. Name the file [name]-chat-history.md. First show me the text in the chat. Until I write ok, don't create or save the file.”
  2. 2

    Read it and correct it

    Check three things: are these the prompts that gave a good result (compare with the last good one), is there anything extra, is anything important missing. Something wrong? Say exactly what to change, for example “add to the rules section: …” or “remove the part about…”. Claude will show the text again: read all of it, not only the changed spot.

  3. 3

    Save it in your project

    When the text is right, write “ok, save the file in the project”. Then open the list of project files and make sure the file is there. If it isn't, and Claude gave you only text or a file in the chat, download the file (or copy the text into a new .md file) and add it through Context → Add.

    Important: read the text once more before saving: passwords, keys and personal data do not belong in the file.

  4. 4

    Test it in a new chat

    This is the most important step. Open a new chat inside the project and send:

    “Read the file [name]-chat-history.md from this project. If you can't find it, say so and don't make anything up. Then tell me: what stage the reel is at, which prompts are the latest approved, and which rules and open questions are written in the file. Then wait for my command.”

    Compare the answer with the file. Does it match? Carry on. Something missing? Go back to the old chat, ask it to complete the file, save the new version under the same name and test again. Delete the old chat only after the test passes. If you'd rather not, just stop using it and keep it.

Once a month: check your files

This is a separate job, useful once your project has several files. Files pile up: repeats appear, things that are no longer true, and rules that argue with each other. Claude takes all the project files into account, and when they argue, it may pick the wrong one. I don't delete files without a reason, but once a month I ask Claude to check them. First download your important files to your device, so you can go back to the earlier version. Then send this in your project chat:

“Check all the files in the project. Find repeats inside files and between them, data that may no longer be true, and rules that argue with each other. Make a numbered list: what you suggest deleting, merging or fixing, and why; for each item name the file and quote the text. If you're not sure data is outdated, mark it “not sure” and don't suggest deleting it. Don't merge the history files of different reels. Don't change or delete anything: I'll look at the list and tell you what to do.”

What next. Look through the list. For what you agree to fix, write: “Do items 1, 3 and 5 from your last list. Show the new text of each file and don't save until I write ok”. Read the new texts in full: Claude may have quietly changed other places too. Remove a file you no longer need from the project file list yourself, and only after you've downloaded a copy.

Check. There is a history file in the project, and the new chat's answer matches what is written in the file (stage, prompts, rules, what's undecided). If you did the monthly check: you have downloaded copies, and you read the new texts in full.

8 · Автоматизация

Пусть Claude напоминает и считает за тебя

В рилзах много рутины, о которой легко забыть: выложить анонс в Stories, не дать закончиться запасу рилзов, не пропустить праздник. Для этого есть задача по расписанию. В нужный день и час Claude запускается сам, делает работу и присылает результат письмом.

Что нужно знать сразу

  • Нужен платный тариф. На октябрь 2026 задачи по расписанию есть на платных тарифах Claude, а на бесплатном их нет. Проверь актуальные условия в справке Claude. Если у тебя бесплатный тариф, читай раздел как справку на будущее.
  • Создавать удобнее в приложении на компьютере. На телефоне и в веб-версии эта функция пока в бета-версии и может работать с перебоями. Созданная задача потом работает без компьютера.
  • Задача работает на серверах Claude, а не на твоём устройстве, поэтому компьютер может быть выключен. Но иногда запуск пропускается, поэтому раз в неделю смотри журнал запусков в разделе Scheduled.
  • Что видит задача. Подключённые сервисы (ниже) и, если создана из чата твоего проекта, файлы этого проекта. Обычная такая задача не видит папки на твоём компьютере.

Какие сервисы подключить (коннекторы)

Коннектор — это твоё разрешение Claude заходить в сервис: в почту, календарь, диск. Без него задача не сможет отправить письмо или найти файл. Раздел называется Connectors; в русском интерфейсе названия разделов могут отличаться, ищи похожее. Вот сервисы, которые использую я:

  • Gmail

    начни с него

    Задача присылает результат на твою почту. Нет Gmail? Заведи бесплатный ящик: он нужен только для писем от Claude.

    Как подключить: плюс в окне чата → Connectors → включить Gmail → войти в аккаунт Google.

    Важно: коннектор получает доступ ко всей почте аккаунта. Лучше подключить отдельный личный ящик, а не рабочий.

  • Google Календарь

    по желанию

    Письма, которые ты отправил сам себе, телефон часто не озвучивает. Календарь решает это: Claude может создать событие-напоминание; сигнал зависит от настроек уведомлений твоего телефона.

    Как подключить: так же, как Gmail.

  • Google Диск

    по желанию

    Задача находит нужный файл (у меня это папка с анонсами для Stories). Анонс — короткое видео в Stories, которое сообщает, что скоро выйдет рилз.

    Как подключить: так же, как Gmail.

  • vidIQ

    по желанию, для разделов 9 и 10

    Статистика твоего аккаунта и поиск чужих рилзов с большим числом просмотров. Каждый запуск такой задачи тратит кредиты, их число зависит от тарифа vidIQ. Не делай таких задач много и следи за остатком.

    Как подключить: Settings → Connectors → добавить свой коннектор → вставить адрес подключения https://mcp.vidiq.com/mcp → войти в vidIQ. Адрес сверь с актуальной справкой vidIQ: вставляй только тот, что указан там. Свой Instagram привяжи на app.vidiq.com. По описанию vidIQ, работает с публичным профилем, которым ты владеешь.

Как создать автоматизацию: пять шагов

  1. 1

    Реши, что и когда

    Ответь себе на четыре вопроса: когда запускать? Что взять на входе (файл, сайт)? Что сделать? Что прислать и когда промолчать? Пример: «раз в месяц найти в интернете праздники на ближайшие два месяца и прислать мне список с идеями рилзов».

  2. 2

    Подключи нужные сервисы

    Для первой задачи хватит Gmail. Какие коннекторы нужны другим задачам, смотри в таблице в конце раздела.

  3. 3

    Отправь фразу в чате проекта

    Открой свой проект (раздел Projects в левом меню) и начни в нём новый чат: внутри проекта, не вне него. Так задача сможет читать файлы проекта (у меня так работает). Вставь фразу и замени текст в квадратных скобках своим: сами скобки и слово «например» удали, пустых скобок не оставляй. Не знаешь, что написать в «Что делать»? Возьми пример из блока ниже или опиши обычными словами, как объяснил бы помощнику.

    «Создай задачу по расписанию. Мой часовой пояс: [твой город]. Когда: [например: каждый день в 12:30]. Что делать: [опиши своими словами, по шагам]. Результат пришли письмом только на [адрес подключённого Gmail], никому другому не отправляй. Письмо короткое, чтобы читалось с телефона. Если по описанным мной условиям присылать нечего, письмо не присылай. Если не смог выполнить задачу (нет файла, нет доступа), пришли короткое письмо с темой «Ошибка задачи». Ничего не придумывай. Сначала коротко перескажи, как ты понял задачу, потом задай все вопросы сейчас, при создании. При запуске по расписанию меня не будет рядом, поэтому тогда ничего не спрашивай и действуй по этому описанию.»

    Claude перескажет задачу и задаст уточняющие вопросы. Ответь, поправь и напиши ок в чате: тогда Claude создаст задачу и сообщит об этом, а она появится в разделе Scheduled. При первом запуске Claude может спросить твоё разрешение перед отправкой письма: это режим подтверждений, о нём ниже в правилах.

    Есть и ручной способ: в левом меню приложения открой раздел Scheduled (в русском интерфейсе название может отличаться). Но проще через чат проекта.

  4. 4

    Проверь тестом сразу

    Не жди завтрашнего дня. В том же чате проекта напиши: «Выполни задачу [название] прямо сейчас один раз, как при запуске по расписанию, но отмени только условие «не присылай письмо», всё остальное выполни как обычно. Если задача читает файлы проекта, в конце письма назови файл и что взял из него». Проверь почту, в том числе папку «Спам», и что письмо пришло на нужный адрес. Письмо пришло и текст верный? Хорошо. Задача должна читать файл, а Claude его не назвал? Значит, она не видит проект: создай её заново из чата внутри проекта.

  5. 5

    Следи и правь

    В разделе Scheduled видны прошлые и будущие запуски. Там задачу можно править, ставить на паузу, запускать вручную и удалять. Нужна правка? Напиши в чате проекта: «обнови задачу [название]: письмо слишком длинное, пусть будет не больше пяти строк».

Правила, чтобы автоматизация не навредила

  • Начни с одной задачи. Три письма в день, и ты перестанешь их читать. Письмо должно приходить, только когда есть о чём.
  • Всегда указывай свой часовой пояс. Иначе задача может сработать в другой час.
  • Режим подтверждений — это настройка: спрашивать ли у тебя разрешение перед каждым действием, например перед отправкой письма. Пока он включён, без твоего ответа задача может остановиться. Когда проверил, что всё работает, можно включить автоматический режим в настройках задачи (открой задачу в разделе Scheduled): тогда письма обычно уходят сразу. Раз Claude тогда не спрашивает, в фразе указан единственный адрес, на который можно писать.
  • Задачам, которые удаляют файлы, не давай права, пока не проверил на тестовой папке. У меня есть задача, которая убирает старые анонсы в корзину Google Диска. Я включил её только после проверки. В тексте такой задачи укажи точное название папки и запрет трогать остальное; сначала пусть присылает только список того, что убрала бы. В корзине файлы обычно лежат около 30 дней, если её не очищали (проверь в справке Google).
  • Не пиши в задачу пароли, ключи доступа и ссылки с секретным кодом (токеном) в адресе. Текст задачи хранится в её настройках.
  • Давай задачам понятные названия. Раз в неделю смотри журнал запусков, раз в месяц весь список. У меня одна старая задача частично дублировала новую, и лишнюю пришлось выключить.

Две задачи для начала (выбери одну)

1. Праздники и сезоны (раз в месяц)

Нужен только Gmail. Claude найдёт даты и подскажет, когда начинать рилз. Тест из шага 4 для неё проще: просто попроси выполнить задачу сейчас и пришли письмо в любом случае.

«Создай задачу по расписанию. Мой часовой пояс: [твой город]. Моя страна: [страна]. Моя ниша: [например: AI-арт в стиле фэнтези]. Когда: первого числа каждого месяца в 10:00. Что делать: найди в интернете праздники и сезоны на ближайшие 60 дней, которые подходят для рилзов в моей нише и моей стране. 8 · Automation

Let Claude remind you and do the counting

Reels come with a lot of routine that is easy to forget: posting a teaser to Stories, not letting your stock of reels run out, not missing a holiday. That is what a scheduled task is for. On the day and hour you choose, Claude starts by itself, does the work and sends you the result by email.

What to know right away

  • You need a paid plan. As of October 2026, scheduled tasks are available on paid Claude plans and not on the free one. Check the current terms in the Claude help article. On the free plan, read this section as a reference for later.
  • It is easier to create tasks in the computer app. On the phone and the web version this feature is still in beta and may work unevenly. Once created, the task runs without your computer.
  • The task runs on Claude's servers, not on your device, so your computer can be off. But a run is sometimes skipped, so once a week look at the run log in the Scheduled section.
  • What the task can see. The connected services (below) and, if it was created from a chat in your project, that project's files. An ordinary task like this can't see folders on your computer.

Which services to connect (connectors)

A connector is your permission for Claude to enter a service: your mail, calendar, drive. Without it, a task can't send an email or find a file. The section is called Connectors; section names may differ in other interface languages, so look for something similar. Here are the services I use:

  • Gmail

    start with this

    The task sends the result to your mailbox. No Gmail? Create a free one: you only need it for emails from Claude.

    How to connect: the plus in the chat window → Connectors → turn on Gmail → sign in to your Google account.

    Important: the connector gets access to the whole mailbox of the account. It is better to connect a separate personal mailbox, not a work one.

  • Google Calendar

    optional

    A phone often doesn't make a sound for emails you sent to yourself. The calendar fixes that: Claude can create a reminder event; whether it rings depends on your phone's notification settings.

    How to connect: the same way as Gmail.

  • Google Drive

    optional

    The task finds a file you need (for me it is a folder of teasers for Stories). A teaser is a short video in Stories that says a reel is coming soon.

    How to connect: the same way as Gmail.

  • vidIQ

    optional, for sections 9 and 10

    Your account statistics and a search for other people's reels with a lot of views. Every run of such a task spends credits, and their number depends on your vidIQ plan. Don't create many of them and keep an eye on the balance.

    How to connect: Settings → Connectors → add a custom connector → paste the connection address https://mcp.vidiq.com/mcp → sign in to vidIQ. Check the address against the current vidIQ help article: paste only the one listed there. Link your Instagram at app.vidiq.com. According to vidIQ, it works with a public profile that you own.

How to create an automation: five steps

  1. 1

    Decide what and when

    Answer four questions: when should it run? What is the input (a file, a website)? What should it do? What should it send, and when should it stay silent? Example: “once a month, find holidays for the next two months on the internet and send me a list with reel ideas”.

  2. 2

    Connect the services you need

    For your first task, Gmail is enough. Which connectors other tasks need, see the table at the end of the section.

  3. 3

    Send the phrase in a project chat

    Open your project (the Projects section in the left menu) and start a new chat in it: inside the project, not outside it. That way the task can read the project's files (it works like this for me). Paste the phrase and replace the text in square brackets with your own: delete the brackets and the words “for example”, and don't leave any brackets empty. Not sure what to write in “What to do”? Take an example from the block below or describe it in plain words, as you would to an assistant.

    “Create a scheduled task. My time zone: [your city]. When: [for example: every day at 12:30]. What to do: [describe in your own words, step by step]. Send the result by email only to [the address of the connected Gmail], and to no one else. Keep the email short, readable on a phone. If, by the conditions I described, there is nothing to send, don't send an email. If you couldn't do the task (no file, no access), send a short email with the subject "Task error". Don't make anything up. First briefly retell how you understood the task, then ask all your questions now, while creating it. When it runs on schedule I won't be around, so then ask nothing and act on this description.”

    Claude will retell the task and ask clarifying questions. Answer, correct it and write ok in the chat: then Claude creates the task and tells you so, and it appears in the Scheduled section. On the first run Claude may ask your permission before sending an email: that is confirmation mode, covered below in the rules.

    There is also a manual way: open the Scheduled section in the app's left menu (the name may differ in other languages). But it is simpler through the project chat.

  4. 4

    Test it right away

    Don't wait for tomorrow. In the same project chat write: “Run the task [name] right now, once, as if on schedule, but cancel only the condition "don't send an email"; do everything else as usual. If the task reads project files, at the end of the email name the file and what you took from it.” Check your mail, including the Spam folder, and that the email came to the right address. Did the email arrive and is the text right? Good. The task should read a file, but Claude didn't name it? Then it doesn't see the project: create it again from a chat inside the project.

  5. 5

    Watch and adjust

    In the Scheduled section you can see past and upcoming runs. There you can edit the task, pause it, run it by hand and delete it. Need a change? Write in the project chat: “update the task [name]: the email is too long, make it no more than five lines”.

Rules so automation does no harm

  • Start with one task. Three emails a day, and you stop reading them. An email should arrive only when there is something to say.
  • Always give your time zone. Otherwise the task may run at another hour.
  • Confirmation mode is a setting: whether Claude asks your permission before every action, for example before sending an email. While it is on, the task may stop without your answer. Once you've checked that everything works, you can turn on automatic mode in the task settings (open the task in the Scheduled section): then emails usually go out at once. Since Claude then doesn't ask, the phrase names the single address it may write to.
  • Don't give tasks that delete files any rights until you've tested them on a test folder. I have a task that moves old teasers to the Google Drive trash. I turned it on only after testing. In the text of such a task give the exact folder name and forbid touching anything else; at first let it send only a list of what it would remove. Files usually stay in the trash for about 30 days, unless you emptied it (check Google's help).
  • Don't put passwords, access keys or links with a secret code (a token) in the address into a task. The task text is stored in its settings.
  • Give tasks clear names. Look at the run log once a week and the whole list once a month. One of my old tasks partly duplicated a new one, and I had to turn the extra one off.

Two tasks to start with (pick one)

1. Holidays and seasons (once a month)

You need only Gmail. Claude finds the dates and tells you when to start a reel. The test from step 4 is simpler for it: just ask it to run the task now and send the email in any case.

“Create a scheduled task. My time zone: [your city]. My country: [country]. My niche: [for example: fantasy AI art]. When: on the first day of every month at 10:00. What to do: find holidays and seasons for the next 60 days on the internet that suit reels in my niche and my country. For each one write the date, one reel idea and when it is time to start making it: [number of days, for example 12] days before the holiday (time for scenes and editing). Use only dates confirmed by a source and attach the link; if there is no confirmation, write "to check". Send the result by email only to [the address of the connected Gmail], up to 12 lines. If there is nothing to send, don't send an email. If you couldn't do the task, send a short email with the subject "Task error". First briefly retell how you understood the task, then ask all your questions now, while creating it. When it runs on schedule, ask nothing.”

2. Reel stock (every morning)

Stock is how many days ahead you have reels in Instagram's built-in publishing scheduler. You need Gmail and a posting calendar file in the project: date, time, reel title. No such file? Write to Claude in the project chat: “Create a posting calendar file: a table with date, time and reel title” and add it to the project, as in section 7.

“Create a scheduled task. My time zone: [your city]. When: every day at 10:00. What to do: read the posting calendar file in the project, find the latest reel date in it and calculate exactly how many days are left from today's date in my time zone. Take dates only from the file; if there is no file or date, don't guess. If more than 5 days are left, don't send an email. If 3–5 days, send an email: how many days are left, the date of the last reel and that it is time to make a new one. If 1–2 days, start the subject with the word "Urgent". If 0 or less, say the stock has run out. Send the email only to [the address of the connected Gmail], 5–8 lines. If you couldn't do the task (no file), send a short email with the subject "Task error". First briefly retell how you understood the task, then ask all your questions now, while creating it. When it runs on schedule, ask nothing.”

9 · Аналитика

Как сделать, чтобы выводы возвращались в следующий рилз

Цифры сами рилзы не улучшают. Посмотрел статистику, подумал «надо что-то менять» и сделал новый рилз по-старому: знакомо? Нужен круг: рилз → замер → запись в журнал → вывод → следующий рилз. Тогда Claude обычно сам прочитает перед сценарием, что работает, и применит это. Проверь на первом же сценарии: шаг 4 ниже.

Своя аналитика

обе линии ведут в журнал гипотез

Правую линию мы разберём в разделе 10 «Поиск удачных рилзов». Пока идеи в журнал гипотез ты записываешь сам.

Два файла и одно правило

  • Журнал результатов. Одна строка на рилз: дата выхода, начало подписи (по нему рилз узнают), длина, просмотры, пролистали, среднее время просмотра, досмотрели, сохранили, поделились, группа, дата замера.
  • Журнал гипотез. Гипотеза — это идея, которую ты проверяешь. Например: «зацикленный финал увеличивает досмотр». Для каждой записаны: откуда взялась, как применить, главная метрика (по какой цифре судим) и статус. Внизу этого же файла есть раздел «Выводы, которые применяем»: сюда переезжают гипотезы со статусом «похоже, помогло». Это и есть правила для следующих рилзов.
  • Правило в инструкциях проекта (шаг 4). Оно заставляет Claude читать оба журнала перед сценарием.

Слова без жаргона

  • Пролистали — доля людей, ушедших с рилза почти сразу. Чем меньше, тем лучше. В приложении это может называться «Пропустили» или «Skip rate». Если такого показателя у тебя нет, ставь прочерк.
  • Досмотрели — какую часть ролика смотрят в среднем: среднее время просмотра ÷ длина ролика, в процентах. Это считает Claude, а длину ты называешь сам.
  • Сохранили, поделились — в приложении это числа. Claude делит их на просмотры и записывает в процентах.
  • Главная метрика — одна цифра, по которой судим о гипотезе. Выбирай её среди удержания (пролистали, досмотрели). Просмотры не годятся: они больше зависят от темы и рекомендаций, чем от твоей правки.
  • Контрольный рилз — обычный рилз, в котором ты не проверяешь никакую гипотезу. Тема и сцены у него свои, это нормально: сравнение получается грубым, зато честным. Тестовый рилз (тест №N) — рилз с проверяемой гипотезой номер N.
  • Медиана — если выстроить результаты по порядку, это тот, что посередине.

Откуда брать цифры

Основной путь — приложение Instagram: кнопка «Статистика» под рилзом (нужен профессиональный аккаунт: автор или бизнес). Сделай 1–2 скриншота: главный экран статистики рилза и экран про просмотры и удержание, если он есть. Если какой-то цифры на скриншоте нет, в журнале будет прочерк. Это нормально. Если подключён vidIQ (раздел 8 «Автоматизация»), часть цифр можно брать через него, но долю из Рекомендаций, долю неподписчиков и график удержания по секундам он не отдаёт: их смотри в приложении.

Как построить круг: четыре шага

Шаг 4 короткий и стоит последним, но от него зависит всё остальное. Не пропускай.

  1. 1

    Создай два файла

    В чате своего проекта отправь:

    «Создай в проекте два файла. 1) Журнал результатов рилзов: таблица с колонками: дата выхода, начало подписи, длина в секундах, просмотры, пролистали %, среднее время просмотра, досмотрели %, сохранили %, поделились %, группа, дата замера. Даты пиши как ДД.ММ.ГГГГ. 2) Журнал гипотез: таблица с колонками: номер, гипотеза, откуда взялась, как применить, главная метрика, статус; под таблицей раздел «Выводы, которые применяем». Допустимые статусы: «проверяем», «ждёт моего подтверждения», «похоже, помогло», «похоже, не помогло», «разницы не видно». В начало журнала гипотез впиши правила: на один рилз одно изменение; вывод по гипотезе делаем, когда есть минимум 3 рилза «тест» и минимум 3 рилза «контроль»; если главная метрика у каждого теста лучше, чем у всех контролей, статус «похоже, помогло», если у каждого теста хуже, чем у всех контролей, «похоже, не помогло», иначе «разницы не видно»; пока тестов меньше трёх, вывода нет; строки с группой «не указана» в выводы не берём; любой вывод перепроверяем ещё одним рилзом. Сначала покажи оба файла. Сохрани их в проекте, только когда я напишу «сохраняй файлы».»

    Уже выпущенные рилзы без проверяемой идеи можно внести задним числом как «контроль»: так ты быстрее наберёшь 3 контрольных. А вот 3 теста по одной гипотезе — это минимум 3 новых рилза, то есть недели две-три работы. Так и задумано: быстрых выводов тут не бывает.

  2. 2

    Замеряй на 3-й день

    Через три дня после выхода (три дня — условность, но все рилзы замеряем в одном возрасте) открой статистику рилза, сделай скриншот и отправь в чат проекта. Поставь напоминание в телефоне заранее, в день выхода рилза.

    «Вот статистика рилза [название], он вышел [дата]. Длина [секунд], подпись начинается так: [первые слова]. Внеси строку в журнал результатов. Группа: [контроль или тест №N]. Посчитай досмотр, сохранения и репосты в процентах. Если цифры на скриншоте нет, ставь прочерк и ничего не вычисляй из других показателей. Покажи мне строку. Выводы только перескажи словами, в журнал гипотез ничего не записывай, пока я не подтвержу.»

    Один рилз ничего не доказывает: просмотры сильно скачут из-за темы, времени и дня выхода. Поэтому тест и контроль выпускай в похожее время и в похожий день недели. Раз в месяц сверь пару чисел из журнала со скриншотом: Claude иногда ошибается в арифметике.

  3. 3

    Записывай гипотезы

    Заметил закономерность в статистике или в чужом рилзе? Запиши её одной фразой. Гипотеза из чужого рилза — это предположение, а не факт: ради этого и нужен тест.

    «Запиши в журнал гипотез: [что и как проверяем, например: зацикленный финал, когда последняя сцена переходит в первую, увеличивает досмотр]. Откуда взялась: [свои слова, например: заметил в чужом рилзе]; не придумывай источник. Главную метрику предложи сам из удержания (пролистали или досмотрели) и жди моего ок. Рилз с этой гипотезой должен отличаться от контрольных только одним изменением.»
  4. 4

    Обязательно: вставь правило в инструкции проекта

    Без этого шага Claude может не заглянуть в журнал. Сначала скачай копию своего файла с правилами (обычно preferences.md; про инструкции проекта мы говорили в разделе 4 «Инструкции проекта»). Потом отправь в чате проекта:

    «Найди в проекте файл с моими правилами (обычно preferences.md). Если его нет, ничего не создавай, а спроси, где мои инструкции. Добавь туда правило: каждый раз, когда я прошу сценарий нового рилза, и только тогда, сначала прочитай журнал гипотез и журнал результатов. Примени только выводы со статусом «похоже, помогло» и скажи мне, какую одну гипотезу мы проверяем в этом рилзе. Если журнал пуст или подходящей гипотезы нет, так и скажи и предложи выбрать. Остальной текст файла не меняй и не сокращай. Если похожее правило уже есть, покажи его и спроси, заменить ли. Сначала покажи файл целиком и отдельно добавленную строку. Сохрани только когда я напишу «сохраняй правило».»

    Проверь: начни сценарий нового рилза. Claude должен сам сказать, какую гипотезу вы проверяете (если журнал пуст, он скажет и это). Не сказал — напомни, что правило есть в файле с твоими правилами.

Правила честного чтения

  • Меняй одно за раз. Иначе не поймёшь, что именно сработало.
  • Это грубый ориентир, не доказательство. У рилзов всегда меняются тема, музыка, обложка. Поэтому даже «похоже, помогло» перепроверь ещё одним рилзом, а через месяц ещё раз.
  • Журнал не заменяет здравый смысл. Если вывод звучит странно, попроси Claude показать цифры, из которых он получился, и сверь их со скриншотом.

Необязательно, на потом: пусть цифры собираются сами

Нет vidIQ — пропусти этот блок. Когда круг заработает вручную, часть работы можно отдать задачам по расписанию (как их создавать, см. раздел 8 «Автоматизация»; там же про подключение Gmail и vidIQ). Что нужно знать до включения:

  • Задачи используют vidIQ и тратят его кредиты при каждом запуске, даже если нового рилза нет. Посмотри баланс до включения и начни с запуска раз в 2–3 дня. Выключить задачу можно в разделе Scheduled.
  • Задачи сами меняют файлы проекта. Скачай копии журналов до первого запуска. Gmail должен быть подключён: проверь адрес, чтобы письмо не ушло чужому.
  • Задачи только читают данные аккаунта и ничего в нём не публикуют и не меняют.
  • В автоматическом режиме выводы записываются только как «ждёт моего подтверждения». Правилом вывод становится, когда ты сам написал ок.

Находит рилзы, которым 3–5 дней, и вносит их в журнал результатов.

При запуске по расписанию ничего не спрашивай: если чего-то не хватает, пропусти этот шаг и напиши об этом в письме.»

Задача 2: недельный разбор

Собирает отчёт за неделю: что набрало много просмотров, что просело, что менять.

«Создай задачу по расписанию. Если Gmail не подключён, сначала скажи мне и не создавай задачу. Мой часовой пояс: [твой город]. Когда: каждый понедельник в 10:00. 9 · Analytics

How to make the lessons flow back into your next reel

Numbers don't improve reels on their own. You look at the stats, think "I should change something", and then make the next reel the old way. Sound familiar? You need a loop: reel → measurement → log entry → conclusion → next reel. Then Claude will usually read what works before writing a script and apply it. Check this on your first script: step 4 below.

Your own analytics
Reel published→Measure on day 3→Results log
Ideas from other people's reels (section 10)
Scouting others' reels→What repeats
both lines lead to the hypothesis log
Hypothesis log→Next reel→Measure again

We cover the right-hand line in section 10, "Finding successful reels". For now you add ideas to the hypothesis log yourself.

Two files and one rule

  • Results log. One row per reel: publish date, start of the caption (that's how you recognise the reel), length, views, skipped, average watch time, watched, saved, shared, group, measurement date.
  • Hypothesis log. A hypothesis is an idea you are testing. For example: "a looping ending increases watch-through". Each one records: where it came from, how to apply it, the main metric (the number you judge it by) and a status. At the bottom of the same file there is a section called "Conclusions we apply": hypotheses with the status "looks like it helped" move here. These are the rules for your next reels.
  • A rule in the project instructions (step 4). It makes Claude read both logs before a script.

Words without jargon

  • Skipped — the share of people who left the reel almost immediately. Lower is better. In the app it may be called "Skipped" or "Skip rate". If you don't have this number, put a dash.
  • Watched — how much of the video people watch on average: average watch time ÷ video length, as a percentage. Claude calculates it; you give the length.
  • Saved, shared — in the app these are plain counts. Claude divides them by views and writes percentages.
  • Main metric — the one number you judge a hypothesis by. Pick it from retention (skipped, watched). Views don't work: they depend more on the topic and recommendations than on your change.
  • Control reel — an ordinary reel where you are not testing any hypothesis. Its topic and scenes are its own, and that's fine: the comparison is rough, but honest. Test reel (test #N) — a reel testing hypothesis number N.
  • Median — line the results up in order; the median is the one in the middle.

Where to get the numbers

The main way is the Instagram app: the "Insights" button under the reel (you need a professional account: creator or business). Take 1–2 screenshots: the main insights screen of the reel and the screen about views and retention, if you have one. If a number isn't on the screenshot, the log gets a dash. That's fine. If vidIQ is connected (section 8, "Automation"), some numbers can come through it, but it doesn't provide the share from Recommendations, the non-follower share or the second-by-second retention graph: look those up in the app.

How to build the loop: four steps

Step 4 is short and comes last, but everything else depends on it. Don't skip it.

  1. 1

    Create two files

    In your project chat, send:

    “Create two files in the project. 1) Reels results log: a table with columns: publish date, caption start, length in seconds, views, skipped %, average watch time, watched %, saved %, shared %, group, measurement date. Write dates as DD.MM.YYYY. 2) Hypothesis log: a table with columns: number, hypothesis, where it came from, how to apply, main metric, status; under the table a section "Conclusions we apply". Allowed statuses: "testing", "waiting for my confirmation", "looks like it helped", "looks like it didn't help", "no visible difference". At the top of the hypothesis log write these rules: one change per reel; we draw a conclusion about a hypothesis only when there are at least 3 "test" reels and at least 3 "control" reels; if the main metric of every test is better than all controls, the status is "looks like it helped"; if every test is worse than all controls, "looks like it didn't help"; otherwise "no visible difference"; while there are fewer than three tests there is no conclusion; rows with group "not specified" are not used in conclusions; every conclusion gets re-checked with one more reel. First show me both files. Save them in the project only when I write "save the files".”

    Reels you already published that tested no particular idea can be entered retroactively as "control": that gets you to 3 controls faster. But 3 tests of one hypothesis means at least 3 new reels, so two or three weeks of work. That's by design: there are no quick conclusions here.

  2. 2

    Measure on day 3

    Three days after publishing (three days is a convention, but every reel is measured at the same age), open the reel's insights, take a screenshot and send it to the project chat. Set a phone reminder in advance, on the day the reel goes out.

    “Here are the stats for the reel [name], published on [date]. Length [seconds], the caption starts with: [first words]. Add a row to the results log. Group: [control or test #N]. Calculate watched, saved and shared as percentages. If a number isn't on the screenshot, put a dash and don't work it out from other figures. Show me the row. Only retell any conclusions in words; don't write anything to the hypothesis log until I confirm.”

    One reel proves nothing: views jump around because of topic, time and day of posting. So publish test and control reels at a similar time and on a similar day of the week. Once a month check a couple of numbers in the log against the screenshot: Claude sometimes makes arithmetic mistakes.

  3. 3

    Write down hypotheses

    Noticed a pattern in your stats or in someone else's reel? Write it in one sentence. A hypothesis from someone else's reel is a guess, not a fact: that's exactly why you test it.

    “Add to the hypothesis log: [what and how we test, for example: a looping ending, where the last scene flows into the first, increases watch-through]. Where it came from: [your own words, for example: noticed it in someone else's reel]; don't invent a source. Suggest the main metric yourself from retention (skipped or watched) and wait for my OK. A reel with this hypothesis must differ from the control reels in only one change.”
  4. 4

    Must do: put the rule into the project instructions

    Without this step Claude may not look at the log. First download a copy of your rules file (usually preferences.md; we covered project instructions in section 4, "Project instructions"). Then send in the project chat:

    “Find the file with my rules in the project (usually preferences.md). If it doesn't exist, create nothing and ask me where my instructions are. Add this rule there: every time I ask for a script for a new reel, and only then, first read the hypothesis log and the results log. Apply only conclusions with the status "looks like it helped" and tell me which one hypothesis we are testing in this reel. If the log is empty or there is no suitable hypothesis, say so and offer to choose one. Do not change or shorten the rest of the file. If a similar rule already exists, show it and ask whether to replace it. First show me the whole file and, separately, the line you added. Save only when I write "save the rule".”

    Check: start a script for a new reel. Claude should tell you on its own which hypothesis you are testing (if the log is empty, it will say that). If it doesn't, remind it that the rule is in your rules file.

Rules for honest reading

  • Change one thing at a time. Otherwise you won't know what worked.
  • This is a rough guide, not proof. Reels always differ in topic, music and cover. So even "looks like it helped" should be re-checked with one more reel, and again in a month.
  • The log doesn't replace common sense. If a conclusion sounds strange, ask Claude to show the numbers behind it and compare them with the screenshot.

Optional, for later: let the numbers collect themselves

No vidIQ? Skip this block. Once the loop works by hand, you can hand part of the work to scheduled tasks (how to create them: section 8, "Automation"; it also covers connecting Gmail and vidIQ). What to know before switching them on:

  • The tasks use vidIQ and spend its credits on every run, even when there is no new reel. Check your balance first and start with a run every 2–3 days. You can switch a task off in the Scheduled section.
  • The tasks change project files on their own. Download copies of the logs before the first run. Gmail must be connected: check the address so the email doesn't go to someone else.
  • The tasks only read account data and publish or change nothing in the account.
  • In automatic mode, conclusions are written only as "waiting for my confirmation". A conclusion becomes a rule only when you write OK yourself.

Task 1: regular measurement

Finds reels that are 3–5 days old and adds them to the results log.

“Create a scheduled task. If Gmail isn't connected, tell me first and don't create the task. My time zone: [your city]. When: every 2 days at 12:00. What to do: read the results log and the hypothesis log in the project. If a file is missing, create nothing and send an email with the subject "Task error". Through vidIQ find my reels published 3–5 days ago. Before writing, check by publish date and caption start that such a row doesn't exist yet. For each one calculate exactly: views, skipped %, average watch time, watched %, saved %, shared %. If vidIQ doesn't provide a metric, put a dash and don't derive it from others. Only add new rows at the end of the log; don't change or delete existing rows or files. Determine the group from the hypothesis log; if it isn't specified, write "group not specified". If there are enough reels for a conclusion under the log's rules, write the conclusion to the hypothesis log with the status "waiting for my confirmation". Only read account data; publish and change nothing. Email me only at [address of the connected Gmail] and only if there is a new conclusion or the task could not run (subject "Task error"). First briefly retell how you understood the task, then ask me all your questions now, at creation. When running on schedule, ask nothing: if something is missing, skip that step and say so in the email.”

Task 2: weekly review

Builds a weekly report: what got lots of views, what dropped, what to change.

“Create a scheduled task. If Gmail isn't connected, tell me first and don't create the task. My time zone: [your city]. When: every Monday at 10:00. What to do: through vidIQ take my reels from the last 7 days. Show reels younger than 3 days on a separate line and leave them out of conclusions; give each reel's age in the table. Build the report from these parts: Summary; Reels table (age, views, skipped %, average watch time, saved %, shared %); What got lots of views and what dropped (compare with the median of my reels over the last 4 weeks); What to watch next; What to change; What the data is missing (what vidIQ doesn't provide). If the project has a previous report of the same kind, compare with it. Calculate numbers exactly. Don't draw conclusions from data that isn't there. Only read account data. Save the report in the project as a new file named like 2026-10-05-statistika.md (the Monday's date); if that file already exists, add -2 to the name and don't replace it. Email me a short summary of 3–5 sentences only at [address of the connected Gmail]. If you couldn't complete the task, send a short email with the subject "Task error". First briefly retell how you understood the task, then ask me all your questions now, at creation. When running on schedule, ask nothing: if something is missing, skip that step and say so in the email.”

Check. The project has a results log and a hypothesis log (open the project's file list and confirm), the log has at least one row, your rules file contains the hypothesis rule, and Claude started a new script by asking which hypothesis you are testing. If you switched on scheduled tasks: they show in the Scheduled list and you know how to switch them off.

10 · Поиск удачных рилзов

Как узнать, что сейчас набирает просмотры у других

Нужен vidIQ (сервис статистики по соцсетям, который подключается к Claude). Если он не подключён, этот раздел пропусти. Как подключить, написано в разделе 8.

Когда vidIQ подключён, Claude находит рилзы, которые набрали намного больше просмотров, чем обычно у их авторов. Такие рилзы называем «выстрелами». Claude рассказывает, что у них общего. Ты не копируешь чужое: берёшь один приём (например, как начинается первая секунда) и проверяешь его в своём рилзе. Сначала сделаешь это вручную раз в неделю, потом по желанию отдашь задаче по расписанию.

Делает Claude
Ищет в vidIQ→Убирает лишнее→Пишет выпуск→Предлагает идею
Делаешь ты
Читаешь выпуск→Пишешь «да»→Идея в журнале гипотез→Проверяешь в рилзе

Что понадобится

  • Подключённый vidIQ (раздел 8).
  • Журнал гипотез из раздела 9 (там шаг 1 его создаёт). Если журнала ещё нет, сначала сделай его: сюда Claude будет записывать идеи.
  • Чат твоего Claude-проекта: открой проект и нажми «Новый чат» внутри него. Все фразы ниже пишем туда.
  • Около 10–15 минут на первый раз, не считая подключения vidIQ.

Три шага

  1. 1

    Создай файл для выпусков

    Где: чат проекта. Кого просить: Claude. Скопируй фразу и отправь:

    «Создай в проекте файл «Дайджест чужих удачных рилзов». Вверху напиши короткую подсказку, как им пользоваться. Ниже будут выпуски, новый всегда сверху. Внизу сделай раздел «Уже показано»: туда пойдут ссылки на показанные рилзы, чтобы они не повторялись. Даты пиши так: ДД.ММ.ГГГГ. Сначала покажи мне файл в чате. Если такой файл в проекте уже есть, не перезаписывай его, а скажи мне. Сохрани файл, только когда я напишу «сохраняй файл».»

    Что будет: Claude пришлёт черновик файла. В проекте пока ничего не меняется.

    Что делать дальше: прочитай черновик. Всё нравится? Напиши сохраняй файл. Хочешь поправить? Напиши словами, например: «Добавь в подсказку, что выпуски выходят раз в неделю», и потом снова «сохраняй файл».

    Проверь: открой список файлов проекта (на телефоне: раздел «Файлы» внутри проекта). Там должен быть «Дайджест чужих удачных рилзов». Не появился? Напиши Claude: «Файла в списке нет. Сохрани его ещё раз и скажи, как он называется».

  2. 2

    Попроси первый выпуск

    Где: тот же чат проекта. Кого просить: Claude. В vidIQ он заходит сам (если vidIQ подключён), тебе открывать его не нужно.

    Сначала опиши свою нишу. Одно предложение: что ты делаешь и в каком стиле. По нему Claude поймёт, какие рилзы тебе подходят. Примеры:

    • «Фэнтези-арт: анимированные картинки сказочных миров, нейросеть, мягкие цвета».
    • «Мотивационные рилзы на русском: короткие фразы на фоне природы».
    • «Домашняя кухня: быстрые рецепты, съёмка сверху, без разговоров».

    Слов вроде «арт» или «еда» мало: Claude принесёт всё подряд.

    Теперь фраза. Вставь своё описание вместо слов в квадратных скобках. Сами скобки удали. Потом отправь:

    «Найди через vidIQ рилзы Instagram, которые набрали намного больше просмотров, чем обычно у их авторов. Мне нужны именно такие «выстрелы». Моя ниша и стиль: [опиши, что ты делаешь и в каком стиле]. Смотри последние 14 дней, от 50 тысяч просмотров. Сделай два поиска: по моей нише и по сильным началам (первые три секунды). Сначала прочитай файл «Дайджест чужих удачных рилзов» в проекте. Если его нет, остановись и скажи мне. Не бери рилзы из его раздела «Уже показано». Если рилзов мало или нет совсем, так и скажи, порог просмотров не снижай. Убери лишнее без вопросов: фильмы и сериалы, рекламу приложений, показы инструментов, чужих известных героев, всё не из моей ниши. Авторов называй «автор А», «автор Б», без имён, но у каждого рилза дай ссылку. Напиши выпуск: таблица (автор, ссылка, просмотры, во сколько раз больше обычного, что в рилзе); «Что повторяется» (приёмы, которые встретились у нескольких авторов); «Что можно попробовать»; «Осторожно» (чего ты не смог проверить). Покажи выпуск мне в чате. В файл его запиши, только когда я напишу «сохраняй выпуск». После выпуска предложи ОДНУ идею из «Что повторяется» для моего следующего рилза и спроси, записывать ли её в журнал гипотез. Если повторов нет, так и скажи и ничего не придумывай. Без моего ответа в журнал ничего не пиши.»

    Что будет: в первый раз Claude спросит разрешение на vidIQ. Разреши (кнопка может называться чуть иначе). Через несколько минут, иногда дольше, он пришлёт выпуск в чат. Если vidIQ даст ошибку или кончатся кредиты, Claude должен так и сказать. Открой одну-две ссылки из таблицы и убедись, что такие рилзы есть.

    Что делать дальше: прочитай выпуск. Нормально? Напиши сохраняй выпуск: Claude добавит его в файл сверху, а показанные рилзы запишет внизу в «Уже показано». Результаты не про твою тему? Напиши: «Это не моя ниша. Я делаю [опиши точнее]. Убери лишнее и покажи заново».

  3. 3

    Ответь на предложенную идею

    В конце выпуска Claude предложил одну идею и спросил, записывать ли её. Это единственное решение, которое нужно принять тебе.

    • Хочешь проверить идею. Напиши: Да, запиши в журнал гипотез, источник: дайджест. Claude запишет её сам.
    • Не хочешь. Напиши: Нет, предложи другую. Или просто дождись следующего выпуска.
    • Журнала гипотез в проекте нет. Claude должен сказать, что записывать некуда. Сначала сделай журнал (раздел 9, шаг 1).

    Моё правило: приём, который повторился в двух выпусках подряд, уже стоит проверки. Как проверять, написано в разделе 9: одна идея в одном рилзе.

Необязательно, на потом: пусть выпуск приходит сам

Нет vidIQ: пропусти. Когда ты сделал два-три выпуска вручную и они полезны, поиск можно отдать задаче по расписанию. Задача каждую пятницу вечером (время запуска может немного плавать) ищет выстрелы, добавляет выпуск в файл, записывает идею в журнал гипотез и присылает короткое письмо. Как создавать задачи и подключать Gmail, написано в разделе 8. Сначала прочитай, что нужно знать:

  • Каждый запуск тратит кредиты vidIQ. Посмотри баланс до включения. Задачи по расписанию лежат в списке задач в твоём приложении (раздел может называться Scheduled или иначе): там же их выключают.
  • Скачай копию файла «Дайджест чужих удачных рилзов» до первого запуска (открой файл в проекте и скопируй его текст в заметки). Задача сама меняет файлы проекта без твоего подтверждения. Раз в месяц открывай файл и журнал: нет ли двойных выпусков и потерянных кусков.
  • Впиши адрес Gmail без опечаток: при ошибке письмо с твоими данными уйдёт чужому человеку. Письмо может попасть в спам.
  • Задача ничего не публикует в Instagram. Она только читает данные, пишет в файлы проекта и шлёт тебе письмо.
  • Идею Claude записывает в журнал гипотез сам, но со статусом «ждёт моего подтверждения». Пока ты не подтвердишь, её не должны использовать в сценарии (проверь, спросив Claude перед сценарием). Подтвердить: напиши «подтверждаю гипотезу [название]». Не нужна: «отклоняю гипотезу [название]».

Что помнить

  • Это выборка, а не весь рынок: vidIQ показывает не все рилзы. Если vidIQ отключился или кончились кредиты, выпуск будет пустым или неполным.
  • Цифры чужих рилзов проверяй по ссылке. Claude может ошибиться и при правке файла.
  • Приём из двух-трёх рилзов остаётся предположением. Работает ли он у тебя, покажет только тест.
  • Описания рилзов в vidIQ (например, «зацикленный ролик») пишет программа. Она может ошибаться.
  • У совсем маленького аккаунта множитель («во сколько раз больше обычного») может раздуть один случайный рилз. Смотри и на просмотры.
  • Чужих героев, сцены и сюжеты не копируем. Берём приём: например, как начинается первая секунда или чем заканчивается ролик. Ссылки и приёмы можно, копии нельзя.
  • Пятничная задача может не запуститься (приложение, подписка, лимиты). Это не ошибка: загляни в список задач.
  • Выпуски не заменяют твой собственный взгляд на аккаунт.

Проверь. В проекте есть файл «Дайджест чужих удачных рилзов», в нём хотя бы один выпуск. Claude предложил идею, а после твоего «да» она появилась в журнале гипотез с пометкой «дайджест». Если включил пятничную задачу: она видна в списке задач, пробный запуск прислал письмо, и ты знаешь, как её выключить.

10 · Finding successful reels

How to see what is getting views for other people right now

You need vidIQ (a social media statistics service that connects to Claude). If it is not connected, skip this section. How to connect it is in section 8.

When vidIQ is connected, Claude finds reels that got far more views than their authors usually get. We call them "hits". Claude tells you what they have in common. You do not copy other people's work: you take one technique (for example, how the first second starts) and test it in your own reel. First you do this by hand once a week, later you can hand it to a scheduled task.

Claude does
Searches vidIQ→Removes the irrelevant→Writes an issue→Suggests an idea
You do
Read the issue→Write "yes"→Idea in the hypothesis log→Test it in a reel

What you need

  • vidIQ connected (section 8).
  • The hypothesis log from section 9 (step 1 there creates it). If you do not have it yet, make it first: Claude will record ideas there.
  • The chat of your Claude project: open the project and press "New chat" inside it. Every phrase below goes there.
  • About 10–15 minutes the first time, not counting connecting vidIQ.

Three steps

  1. 1

    Create a file for the issues

    Where: the project chat. Who to ask: Claude. Copy the phrase and send it:

    "Create a file in the project called "Digest of other people's successful reels". At the top, write a short note on how to use it. Below it will be the issues, the newest always on top. At the bottom, make a section called "Already shown": it will hold links to the reels already shown, so they do not repeat. Write dates as DD.MM.YYYY. First show me the file in the chat. If a file with this name already exists in the project, do not overwrite it, tell me. Save the file only when I write "save the file"."

    What happens: Claude sends a draft of the file. Nothing in the project changes yet.

    What to do next: read the draft. Happy with it? Write save the file. Want changes? Say so in words, for example: "Add to the note that issues come out once a week", and then "save the file" again.

    Check: open the project's file list (on a phone: the "Files" section inside the project). "Digest of other people's successful reels" should be there. Not there? Write to Claude: "The file is not in the list. Save it again and tell me what it is called".

  2. 2

    Ask for the first issue

    Where: the same project chat. Who to ask: Claude. It goes into vidIQ itself (if vidIQ is connected), you do not need to open it.

    First, describe your niche. One sentence: what you make and in what style. Claude uses it to decide which reels fit you. Examples:

    • "Fantasy art: animated pictures of fairy-tale worlds, AI-made, soft colors".
    • "Motivational reels in English: short phrases over nature footage".
    • "Home cooking: quick recipes, shot from above, no talking".

    One or two words like "art" or "food" are too few: Claude will bring back everything.

    Now the phrase. Put your description in place of the words in square brackets. Delete the brackets themselves. Then send:

    "Use vidIQ to find Instagram reels that got far more views than their authors usually get. I am looking for exactly such "hits". My niche and style: [describe what you make and in what style]. Look at the last 14 days, from 50 thousand views. Do two searches: one by my niche and one by strong openings (the first three seconds). First read the file "Digest of other people's successful reels" in the project. If it does not exist, stop and tell me. Do not take reels from its "Already shown" section. If there are few reels or none, say so and do not lower the views threshold. Remove the irrelevant without asking: films and series, app ads, tool demos, other people's famous characters, anything outside my niche. Call authors "author A", "author B", without names, but give a link for every reel. Write an issue: a table (author, link, views, how many times more than usual, what is in the reel); "What repeats" (techniques that appeared at several authors); "What you can try"; "Careful" (what you could not check). Show the issue to me in the chat. Write it into the file only when I write "save the issue". After the issue, suggest ONE idea from "What repeats" for my next reel and ask whether to record it in the hypothesis log. If nothing repeats, say so and invent nothing. Do not write anything to the log without my answer."

    What happens: the first time, Claude asks for permission to use vidIQ. Allow it (the button may be named slightly differently). A few minutes later, sometimes longer, it sends the issue to the chat. If vidIQ returns an error or you run out of credits, Claude should say so. Open one or two links from the table and check that those reels exist.

    What to do next: read the issue. Looks fine? Write save the issue: Claude adds it to the top of the file and records the shown reels at the bottom, in "Already shown". Results not about your topic? Write: "This is not my niche. I make [describe more precisely]. Remove what does not fit and show it again".

  3. 3

    Answer the suggested idea

    At the end of the issue Claude suggested one idea and asked whether to record it. This is the only decision you have to make.

    • You want to test the idea. Write: Yes, record it in the hypothesis log, source: digest. Claude records it itself.
    • You do not. Write: No, suggest another one. Or just wait for the next issue.
    • There is no hypothesis log in the project. Claude should say it has nowhere to record the idea. Make the log first (section 9, step 1).

    My rule of thumb: a technique that repeated in two issues in a row is already worth testing. How to test it is in section 9: one idea in one reel.

  • This is a sample, not the whole market: vidIQ does not show every reel. If vidIQ disconnects or you run out of credits, the issue will be empty or incomplete.

  • A technique seen in two or three reels is still a guess. Only a test will show whether it works for you.

11 · Анонс в Stories

Как рассказать в Stories, что вышел новый рилз

Подписчики видят не все твои рилзы. Stories напоминают тем, кто заходит в приложение: сегодня вышел новый рилз. Это простая реклама своего же рилза. Насколько она помогает, у каждого своё. Это можно проверить (шаг 4).

Два способа

  • Репост рилза в Stories. Открой свой рилз, нажми значок «поделиться» (самолётик) и выбери добавление рилза в Stories. Названия кнопок могут отличаться; если нужной кнопки нет, поищи её в меню рилза.
  • Картинка с надписью. Одна сильная сцена из рилза и короткая надпись: «Новый рилз сегодня» и название.

Выбери любой способ. Репост делается сам, поэтому дальше разбираем картинку: в ней Claude может помочь. Видео и анимацию в гайде не разбираем.

Четыре шага

  1. 1

    Выбери сцену и надпись

    Где: чат проекта. Кого просить: Claude. Замени слова в квадратных скобках, скобки удали, и отправь:

    «Мой рилз «[название]» выходит [дата] в [время]. Что в рилзе: [2–3 предложения о его сценах; если в проекте есть файл с историей этого рилза, напиши «посмотри его в проекте»]. Предложи, какая сцена лучше всего подходит для анонса в Stories (вертикальный формат 9:16), и три варианта короткой надписи на картинку: название рилза и строка «Новый рилз сегодня». Надпись должна быть короткой и стоять не на лице героя и не в самом низу кадра. Только предложи, ничего не меняй в файлах.»

    Что будет: Claude назовёт сцену и пришлёт три варианта надписи. Выбери один или напиши «Сделай короче» или «Ещё варианты».

  2. 2

    Сделай и выложи

    Возьми выбранную сцену: это картинка, из которой ты делал видео, или скриншот кадра из рилза. Добавь надпись как тебе удобно: прямо в Stories (выбери картинку, затем кнопка «Текст»; названия могут отличаться) или в любом редакторе. Выложи в Stories в день выхода рилза.

  3. 3

    Напоминание про анонс (по желанию, можно пропустить)

    Чтобы не забыть выложить анонс, создай на Google Диске папку с названием Анонсы Stories (точно так же, иначе задача её не найдёт) и клади в неё готовые анонсы. Каждый файл называй датой выхода рилза в виде ГГГГ-ММ-ДД (год-месяц-день), например 2026-10-18. Расширение любое: картинка или видео. Дальше Claude может каждый день присылать напоминание письмом. Нужны подключённые Gmail и Google Диск (раздел 8, там же про создание задач). Впиши свой город (чтобы «12:00» было по твоему времени, например «Киев») и адрес Gmail, скобки удали, и отправь в чат проекта:

    «Создай задачу по расписанию. Сначала коротко перескажи, как ты понял задачу, и задай все вопросы сейчас. Задачу создай, только когда я напишу «ок». Если Gmail или Google Диск не подключены, скажи мне и не создавай задачу. Мой город для времени: [город]. Когда: каждый день в 12:00. Что делать при каждом запуске: 1. Открой на Google Диске папку «Анонсы Stories». Если её нет, пришли письмо с темой «Ошибка задачи» на тот же адрес. 2. Найди в ней файл, название которого начинается с сегодняшней даты в виде ГГГГ-ММ-ДД. 3. Если файл есть, пришли письмо со ссылкой на него (если файлов с такой датой несколько, одно письмо со всеми ссылками) и словами: «Сегодня выходит рилз. Выложи анонс в Stories». 4. Если файла нет, ничего не присылай. 5. Только читай. Ничего не удаляй, не переименовывай, не публикуй и не меняй доступ к файлам. Письмо пришли только мне, на [адрес подключённого Gmail], больше никому и на письма не отвечай. Если адрес не указан, письмо не отправляй. При запуске по расписанию ничего у меня не спрашивай: если чего-то не хватает, пропусти этот шаг и напиши об этом в письме.»

    Проверь: напиши в чате «Выполни эту задачу прямо сейчас один раз». Положи в папку тестовый файл с сегодняшней датой, и письмо должно прийти (посмотри и «Спам»). Письмо без звука легко пропустить: для сигнала можно попросить Claude создать событие в календаре, это тоже в разделе 8. Тишина не значит, что всё работает: если письма нет, а файл в папке лежит, загляни в список задач (где он, написано в разделе 8) и убедись, что задача включена. В первые дни проверяй письмо сам.

  4. 4

    Проверь, помогает ли

    Анонс — тоже гипотеза. Один рилз с анонсом и один без ничего не докажут: нужно несколько с анонсом и несколько без и сравнить замеры (цифры из статистики рилза). Как это делать, написано в разделе 9. Время выкладки так же можно проверять.

Что помнить

  • Один анонс ничего не доказывает: просмотры сильно скачут из-за темы и дня выхода.
  • Названия кнопок и разделов Instagram и Claude могут отличаться от тех, что здесь.
  • Не клади в анонс чужие кадры и музыку, на которые у тебя нет прав.
  • В письме напоминания будет ссылка на файл. Не открывай доступ к анонсам всем по ссылке до выхода рилза.
  • Не вставляй в фразы пароли и личные данные. Проверь адрес письма и город после создания задачи.
  • Задача может не запуститься (приложение, подписка, лимиты) и тогда молчит. Если анонсы больше не нужны, выключи её в списке задач.

Проверь. Анонс вышел в день выхода рилза. Если делал картинку: надпись читается и не закрывает лицо героя. Если включил напоминание: папка называется «Анонсы Stories», файлы названы датой выхода, а пробное письмо пришло.

11 · Stories announcement

How to tell your Stories that a new reel is out

Your followers do not see all your reels. Stories remind those who open the app: a new reel is out today. This is simple advertising for your own reel. How much it helps differs for everyone. You can check it (step 4).

Two ways

  • Share the reel to Stories. Open your reel, tap the share icon (the paper plane) and choose to add the reel to Stories. Button names may differ; if you cannot find the button, look in the reel's menu.
  • A picture with text. One strong scene from the reel and a short caption: "New reel today" and the title.

Pick either way. Sharing the reel needs no help, so next we cover the picture: Claude can help with it. We do not cover video or animation in this guide.

Four steps

  1. 1

    Choose a scene and a caption

    Where: the project chat. Who to ask: Claude. Replace the words in square brackets, delete the brackets, and send:

    "My reel "[title]" comes out on [date] at [time]. What is in the reel: [2–3 sentences about its scenes; if the project has a history file for this reel, write "look at it in the project"]. Suggest which scene is best for a Stories announcement (vertical 9:16), and three options for a short caption on the picture: the reel title and the line "New reel today". The caption must be short and must not sit on the hero's face or at the very bottom of the frame. Only suggest, do not change any files."

    What happens: Claude names a scene and sends three caption options. Pick one, or write "Make it shorter" or "More options".

  2. 2

    Make it and post it

    Take the chosen scene: the picture you made the video from, or a screenshot of a frame from the reel. Add the caption however is convenient: right in Stories (choose the picture, then the "Text" button; names may differ) or in any editor. Post it to Stories on the day the reel comes out.

  3. 3

    A reminder for the announcement (optional, you can skip it)

    So you do not forget to post it, create a folder on Google Drive named Stories announcements (exactly like this, otherwise the task will not find it) and put the ready announcements in it. Name each file with the reel's release date as YYYY-MM-DD (year-month-day), for example 2026-10-18. Any extension: picture or video. Then Claude can send you a reminder email every day. You need Gmail and Google Drive connected (section 8, which also covers creating tasks). Fill in your city (so that "12:00" is your local time, for example "Kyiv") and your Gmail address, delete the brackets, and send it in the project chat:

    "Create a scheduled task. First briefly repeat how you understood the task and ask all your questions now. Create the task only when I write "ok". If Gmail or Google Drive is not connected, tell me and do not create the task. My city for the time: [city]. When: every day at 12:00. What to do on every run: 1. Open the folder "Stories announcements" on Google Drive. If it does not exist, send an email with the subject "Task error" to the same address. 2. Find in it a file whose name starts with today's date as YYYY-MM-DD. 3. If the file exists (if several files have that date, one email with all the links), send an email with a link to it and the words: "A reel comes out today. Post the announcement in Stories". 4. If there is no file, send nothing. 5. Only read. Do not delete, rename, publish anything or change file sharing. Send the email only to me, at [address of the connected Gmail], to no one else, and do not reply to emails. If the address is missing, do not send the email. When it runs on schedule, ask me nothing: if something is missing, skip that step and say so in the email."

    Check: write in the chat "Run this task right now, once". Put a test file with today's date into the folder, and the email should arrive (check Spam too). An email without a sound is easy to miss: for an alert you can ask Claude to create a calendar event, also covered in section 8. Silence does not mean everything works: if there is no email but the file is in the folder, look at the task list (section 8 says where it is) and make sure the task is on. Check the email yourself in the first days.

  4. 4

    Check whether it helps

    An announcement is a hypothesis too. One reel with an announcement and one without prove nothing: you need several with and several without, and compare the measurements (the numbers from the reel statistics). How to do this is in section 9. You can test the posting time the same way.

Keep in mind

  • One announcement proves nothing: views jump a lot because of the topic and the day of release.
  • Button and section names in Instagram and Claude may differ from the ones here.
  • Do not put in an announcement other people's footage or music you have no rights to.
  • The reminder email contains a link to the file. Do not open the announcements to everyone with the link before the reel is out.
  • Do not put passwords or personal data into the phrases. Check the email address and the city after the task is created.
  • The task may fail to run (app, subscription, limits) and then stays silent. If you no longer need the announcements, switch it off in the task list.

Check. The announcement went out on the day the reel was released. If you made a picture: the caption is readable and does not cover the hero's face. If you turned on the reminder: the folder is named "Stories announcements", the files are named with the release date and the test email arrived.

12 · Ошибки и чек-лист

Как сделать, чтобы одна ошибка не случилась второй раз

Бывает так: Claude сделал не то, ты поправил, а ошибка вернулась. Правило в preferences.md (раздел 4) помогает, но оно короткое и не говорит, почему ошибка случилась. Нужны две вещи: реестр ошибок (файл-таблица, где у каждой ошибки записано, что случилось и почему) и чек-лист (короткая проверка перед каждым промптом).

Круг ошибок
Ошибка→Запись в реестр→Правило→Пункт в чек-листе→Проверка перед промптом

Как выглядит запись

Пример из моего проекта (картинка для рилза). «Симптом» — что ты видишь не так:

  • Симптом: белые цветы и платье на картинке выбелены.
  • Причина: в моём случае нейросеть пересвечивала светлые сцены, и одной строки про яркость в промпте ей было мало.
  • Правило: писать усиленный блок про яркость и заранее готовить правку «сделать чуть темнее».

Четыре шага

  1. 1

    Создай реестр

    Где: чат проекта. Кого просить: Claude. Отправь:

    «Создай в проекте файл «Реестр ошибок». В нём таблица с колонками: номер, где (рилз или сцена), симптом, причина, правило. Даты пиши так: ДД.ММ.ГГГГ. Пока записей нет, оставь одну пустую строку. Если такой файл в проекте уже есть, не перезаписывай его, а скажи мне, и я решу, что делать. Сначала покажи файл мне. Сохрани его, только когда я напишу «сохраняй файл».»

    Что делать дальше: прочитай черновик и напиши сохраняй файл. Проверь: после этого «Реестр ошибок» появился в списке файлов проекта. Его нет? Напиши: «Файла в списке нет. Сохрани его ещё раз и скажи, как он называется».

  2. 2

    Записывай каждую ошибку сразу

    Результат не тот? Замени слова в скобках, скобки удали, и отправь:

    «Это ошибка: [что не так, своими словами]. Сначала составь запись для файла «Реестр ошибок»: симптом, причина (в моём промпте или в другом месте, честно) и правило, чтобы не повторять. Если причина неясна, так и скажи, не придумывай. Если файла «Реестр ошибок» нет, скажи мне и остановись. Покажи запись мне. Это будет только новая строка, старые не меняй. Запиши её в файл, только когда я напишу «сохраняй запись». После этого покажи исправленный промпт.»

    Что делать дальше: прочитай запись. Причина верная? Напиши сохраняй запись. Нет? Напиши, что неверно, и Claude поправит. Исправляй за одну попытку одну проблему: если менять сразу несколько, обычно появляются новые.

  3. 3

    Собери чек-лист

    Не спеши: после первой ошибки чек-листа ещё нет. Когда в реестре наберётся 5–10 записей (поставь себе напоминание), отправь. Записей меньше? Тоже можно, пункты будут короче:

    «Прочитай «Реестр ошибок» и собери чек-лист для проверки промпта: не больше 10 пунктов, каждый короткой фразой-вопросом (например, «Задан ли размер героя?»). В скобках у каждого пункта напиши номера записей, из которых он взят. Если несколько записей об одном, объедини их в один пункт. Если файл «Чек-лист перед промптом» уже есть, не перезаписывай его, а скажи мне. Покажи чек-лист мне. Сохрани его новым файлом «Чек-лист перед промптом», только когда я напишу «сохраняй чек-лист». Реестр не меняй.»

    Проверь: файл «Чек-лист перед промптом» есть в списке файлов, пунктов не больше десяти.

  4. 4

    Включи проверку перед каждым промптом

    Правило добавляется в файл с правилами (обычно preferences.md, раздел 4). Файла правил ещё нет? Сначала сделай раздел 4. До этого шага сделай копию сам: открой файл в проекте, выдели весь текст и вставь в заметки телефона. Копия от Claude её не заменяет. Потом отправь:

    «Найди в проекте файл с моими правилами (обычно preferences.md). Если его нет, ничего не создавай, а скажи мне. Если файла «Чек-лист перед промптом» нет, тоже скажи мне и остановись. Добавь в файл правил такое правило: перед тем как выдать любой промпт, прочитай «Чек-лист перед промптом» и покажи мне блок «Проверка»: по каждому пункту «да» или «нет» с пояснением. Сам промпт покажи только после моего «ок». Если промпт делается по картинке или файлу, сначала открой его и скажи, что на нём видно, не пиши по памяти; если картинки нет, попроси её. Если новое правило противоречит старому, не выбирай сам, а скажи мне. Если похожее правило уже есть, не дублируй его. Остальной текст файла не меняй и не сокращай. Покажи мне только добавленные строки. Запиши их в тот же файл, только когда я напишу «сохраняй правило».»

    Проверь: попроси новый промпт. Claude обычно сначала показывает блок «Проверка» и ждёт твоего «ок». Если сразу выдал промпт, напиши: «Ты пропустил блок «Проверка», сделай его».

Правило двух неудач

Две неудачные попытки подряд на одной сцене? Остановись и попроси у Claude варианты, а не третий промпт. Например: взять лучшую попытку и исправить монтажом, поправить исходную картинку или упростить сцену. Так обычно уходит меньше времени и попыток.

Что помнить

  • Claude может записать неверную причину. Читай запись до «сохраняй запись».
  • Чек-лист лучше держать коротким: длинный трудно проверять. Объединяй похожие пункты.
  • Правило и блок «Проверка» не дают гарантии: Claude иногда их пропускает. Просто напомни.
  • Claude сохраняет только по твоему слову: «сохраняй файл», «сохраняй запись», «сохраняй чек-лист», «сохраняй правило». Пиши то слово, которое указано во фразе. Если он сохранил сам или не то, напиши «верни как было».
  • Реестр и чек-лист работают, только если оба файла лежат в проекте. Не пиши в них пароли и личные данные. Файлы читаются каждый раз, поэтому держи их короткими.
  • Повторяющиеся правила из реестра можно со временем превратить в скилл (памятку для Claude, раздел 5).

Проверь. В проекте есть «Реестр ошибок» и «Чек-лист перед промптом», в файле с правилами стоит правило про блок «Проверка», а новый промпт Claude начал с блока и ждёт твоего «ок».

12 · Mistakes and checklist

How to stop the same mistake from happening twice

It happens: Claude did something wrong, you fixed it, and the mistake came back. A rule in preferences.md (section 4) helps, but it is short and does not say why the mistake happened. You need two things: a mistake log (a table file where every mistake has what happened and why written down) and a checklist (a short check before each prompt).

The mistake loop
Mistake→Log entry→Rule→Checklist item→Check before the prompt

What an entry looks like

An example from my project (a picture for a reel). "Symptom" is what you see that is wrong:

  • Symptom: white flowers and the dress in the picture are blown out.
  • Cause: in my case the image model overexposed bright scenes, and one line about brightness in the prompt was not enough for it.
  • Rule: write a strengthened brightness block and prepare a "make it a bit darker" correction in advance.

Four steps

  1. 1

    Create the log

    Where: the project chat. Who to ask: Claude. Send:

    "Create a file in the project called "Mistake log". In it, a table with columns: number, where (reel or scene), symptom, cause, rule. Write dates as DD.MM.YYYY. While there are no entries, leave one empty row. If a file with this name already exists in the project, do not overwrite it, tell me, and I will decide what to do. First show me the file. Save it only when I write "save the file"."

    What to do next: read the draft and write save the file. Check: after that, "Mistake log" appears in the project's file list. Not there? Write: "The file is not in the list. Save it again and tell me what it is called".

  2. 2

    Record every mistake right away

    The result is wrong? Replace the words in brackets, delete the brackets, and send:

    "This is a mistake: [what is wrong, in your own words]. First compose an entry for the file "Mistake log": symptom, cause (in my prompt or elsewhere, honestly) and a rule so it does not repeat. If the cause is unclear, say so, do not invent one. If the "Mistake log" file does not exist, tell me and stop. Show me the entry. It is only a new row, do not change the old ones. Write it into the file only when I write "save the entry". After that, show me the corrected prompt."

    What to do next: read the entry. Is the cause right? Write save the entry. If not, write what is wrong and Claude will fix it. Fix one problem per attempt: if you change several at once, new ones usually appear.

  3. 3

    Build the checklist

    Do not rush: after the first mistake there is nothing to build from yet. When the log has 5–10 entries (set yourself a reminder), send this. Fewer entries? That works too, the checklist will just be shorter:

    "Read the "Mistake log" and build a checklist for checking a prompt: no more than 10 items, each a short question (for example, "Is the hero's size given?"). In brackets after each item, write the numbers of the entries it comes from. If several entries are about the same thing, merge them into one item. If the file "Checklist before a prompt" already exists, do not overwrite it, tell me. Show the checklist to me. Save it as a new file "Checklist before a prompt" only when I write "save the checklist". Do not change the log."

    Check: the file "Checklist before a prompt" is in the file list, with no more than ten items.

  4. 4

    Turn on the check before every prompt

    The rule goes into your rules file (usually preferences.md, section 4). No rules file yet? Do section 4 first. Make a copy yourself before this step: open the file in the project, select all the text and paste it into your phone notes. A copy made by Claude does not replace it. Then send:

    "Find the file with my rules in the project (usually preferences.md). If it does not exist, create nothing and tell me. If the file "Checklist before a prompt" does not exist, also tell me and stop. Add this rule to the rules file: before giving me any prompt, read the "Checklist before a prompt" and show me a "Check" block: for every item "yes" or "no" with a short note. Show the prompt itself only after my "ok". If a prompt is made from a picture or a file, first open it and tell me what you see in it, do not write from memory; if there is no picture, ask for it. If the new rule contradicts an old one, do not choose yourself, tell me. If a similar rule already exists, do not duplicate it. Do not change or shorten the rest of the file. Show me only the added lines. Write them into the same file only when I write "save the rule"."

    Check: ask for a new prompt. Claude usually shows the "Check" block first and waits for your "ok". If it gave the prompt at once, write: "You skipped the "Check" block, do it".

The two-failures rule

Two failed attempts in a row on one scene? Stop and ask Claude for options instead of a third prompt. For example: take the best attempt and fix it in editing, fix the source picture, or simplify the scene. This usually saves time and attempts.

Keep in mind

  • Claude can write down a wrong cause. Read the entry before "save the entry".
  • Keep the checklist short: a long one is hard to check. Merge similar items.
  • The rule and the "Check" block are no guarantee: Claude sometimes skips them. Just remind it.
  • Claude saves only on your word: "save the file", "save the entry", "save the checklist", "save the rule". Write the word given in the phrase. If it saved by itself or the wrong thing, write "put it back as it was".
  • The log and the checklist work only if both files are in the project. Do not put passwords or personal data in them. They are read every time, so keep them short.
  • Repeating rules from the log can later become a skill (a reference note for Claude, section 5).
